# 調課雷達 · class-swap-radar

一個給高中老師用的**單檔調課小工具**。點自己課表的某一節，馬上看到「這班還有哪些老師、誰能跟我對調」，並可一步步試調、產生給對方的訊息，供學期中臨時調課使用。

沒有後端、沒有登入、沒有資料庫——就一個 `index.html`。可以本機雙擊打開、丟 GitHub Pages、或用 Claude 的 artifact publish 分享。

> 版本 v1.2.1 · Built by YJL Huang with Claude, Gemini and GPT
> 對外分享的版本（artifact 連結）固定放 DEMO 假資料（全化名），避免真實姓名、課表被公開連結／搜尋引擎索引到；真實課表改用「匯入」在使用者自己裝置上帶入，細節見下方〈資料隱私〉。

## 它能做什麼

- **調課雷達**：點你想搬走的一節 → 依同班任課老師分組，列出誰能對調、哪一節可換、換不了的原因，並標示連堂。
  - 第八節只能跟第八節對調（不會跨到前七節），符合多數學校第八節（輔導課）另計的排課習慣。
- **此刻課堂**：選時間（預設現在）→ 看每班當下誰在上課；也能查某位老師此刻空堂或在哪班。
  - 只要還停在「現在這節」，畫面每 20 秒自動核對一次時間，跨節、跨天會自動跳，不用重新整理或重開頁面；手動切換過時間後就不會被打擾，改用「↻ 回到現在」按鈕自己拉回去。
- **連動試調**：按「確認對調」即在記憶體中換位、即時更新課表，可以再以新課表繼續調第二、第三步；每步不同顏色標記，支援「復原上一步」與「重置課表」。
- **截圖分享**：試調後依對方老師分組，一鍵複製一段可傳 Line 的訊息（含調課路徑），提醒你切到對方課表截圖。
- **資料體檢提示**：匯入後在老師下拉的**上方**用一行黃色提示列出**整份課表**的特殊狀況——缺教師幾筆、共同授課幾格（皆不列入對調），以及疑似重格、疑似撞課（洗檔可能出錯，建議回頭檢查）。這行講的是整份資料、不是你個人的統計，所以標題就寫明「整份資料、非單一老師」。乾淨的課表不會出現這一列。
- **預設顯示自己的課表**：首次進入會問一次「你是哪位老師」，之後每次打開這個網址都直接顯示你的課表；下拉旁有「換人」可以重選或清除。這個記憶跟「匯入的課表」一樣只存在你自己這台裝置的瀏覽器裡，各人各自記錄、互不影響；用下拉切去看同事的課表（例如要截圖傳給他）**不會**改掉「我是誰」。
- **老師下拉依科目分組**：老師一多就難找人，下拉會依科目分組（單層 optgroup），組序照科目在課表資料裡第一次出現的順序，保留原課表的科目排序。
- **手機版面**：課表五天等寬固定，長科目名自然斷行、不縮字，也不會出現左右捲動；連堂等角落標記懸浮在課格右上角，不佔科目名的寬度；第八節單／雙週兩筆上下堆疊，格子會跟著內容長高。
- **匯入自己的課表**：右上「換／匯入課表資料」，貼上或上傳 JSON 即可換一整套資料；載入後會存在使用者自己瀏覽器的本機記憶（localStorage）裡，下次打開同一個網址會自動帶入、不用重新匯入，也可以在匯入視窗按「還原成示範資料」清掉、換回內建 DEMO。這份記憶只留在該台裝置的瀏覽器上，不會上傳、不會被其他打開同一連結的人看到。

## 三種用法

1. **只想試玩**：直接打開 `index.html`，內建示範資料就能點。
2. **用在自己學校**：把你們的班級課表洗成 JSON（見下），用右上匯入貼進去；或把 JSON 直接取代 `index.html` 裡最上面那段 `window.SCHEDULE = [...]`，再 publish／上架。
3. **他校老師**：同一個 `index.html` 就是空殼，匯入你們自己的 JSON 即可，程式完全不用改。

## 資料格式

每一「格課」是一筆物件，整份是一個陣列。範例見 `schedule.sample.json`。

```json
[
  { "cls": "501", "day": 1, "period": 1, "subject": "英語文", "teacher": "林安" },
  { "cls": "501", "day": 5, "period": 6, "subject": "班週會", "teacher": "林安", "fixed": true },
  { "cls": "501", "day": 2, "period": 1, "subject": "多元選修", "teacher": "陳寬", "fixed": true },
  { "cls": "501", "day": 2, "period": 1, "subject": "多元選修", "teacher": "黃立", "fixed": true },
  { "cls": "501", "day": 3, "period": 8, "subject": "英文輔導", "teacher": "林安", "week": "單" },
  { "cls": "501", "day": 3, "period": 8, "subject": "英文輔導", "teacher": "黃立", "week": "雙" }
]
```

| 欄位 | 說明 |
|---|---|
| `cls` | 班級，字串，如 `"501"` |
| `day` | 星期，1–5（一～五） |
| `period` | 節次，1–8 |
| `subject` | 科目名 |
| `teacher` | 老師（可用化名） |
| `fixed` | 選填。`true` = 全校固定節次（班週會／社團／朝週會），或「同一格由多位老師分組上課」的選修課（多元選修、彈性充補、自然探究等）。雷達自動排除、不可對調；分組課的每位老師各佔一筆，雙方課表都看得到自己那筆 |
| `flex` | 選填。`true` = 彈性學習／自主學習等，可不可以換由老師自己判斷，雷達只會標示提醒，不會阻止對調 |
| `week` | 選填。`"單"` / `"雙"` = 隔週輪替課（同一格另有一位老師輪值另一週，兩位老師各自產一筆、都可對調）。雷達會標示提醒，但工具本身沒有「週別」概念，能不能換仍需人工確認是哪一週 |

**同一格多位老師（分組選修／隔週輪替）該怎麼處理：**
- 多元選修、彈性充補、自然探究等「同格多位老師分組上課、本來就不能調」的課，每位老師各自產生一筆、都標 `fixed:true`——這樣兩人的課表上都看得到這節課，但雷達不會誤判成可對調。
- 標示「單／雙」的隔週輪替輔導課，兩位老師各產一筆、可對調，並加 `week` 欄位提醒對調前先確認是哪一週。

**同一格出現多筆時，程式怎麼判斷（順序固定）：**
1. 任一筆有 `week` → 隔週輪替：課表上該格**上下疊成兩列**、各自標「單週／雙週」、各自可點，兩筆都能對調。
2. 同科目 → 共同授課：標「共授」，不列入對調。
3. 全部標 `fixed:true` → 分組選修等合法同節分組（例如本土語文依台語／客語／原住民語拆班，各自不同老師）：本來就不列入對調，不算疑似重格，不出現在提示列。
4. 其餘（不同科目、非全部 `fixed`） → 疑似重格：標「重格?」，不列入對調，並在提示列建議回頭檢查洗檔。

> 修正紀錄：v1.0.0 以前，同一位老師在同一節若因單／雙週輪替而**教到不同班**，課表上只會顯示其中一筆（另一班整個看不到）。現在該格會疊成兩列，兩班都看得到、都能各自點開算雷達。
> 修正紀錄：v1.2.0 以前，本土語文分組（台語／客語／原住民語各自開課，同格不同科目但皆 `fixed:true`）會被誤判成疑似重格。v1.2.1 起這種「全部 fixed」的情形視為合法分組，不再列入提示。

**用「班級課表」當來源，不要用「教師課表」。** 班級課表以全校班級數為單位，天生只含高中部、不必判斷老師屬哪個部；教師課表則會把國中部的課混進來。

## 洗課表資料

把班級課表 PDF 交給 Claude 或 GPT，配合 `wash-prompt.md` 的指示，就能產出上面格式的 JSON。重點規則（如「社團／班週會沒寫老師 = 該節為固定時段」「同格多位老師 → 各產一筆＋fixed:true」「單/雙週輪替 → 各產一筆＋week 標記」）都寫在那份 prompt 裡。Claude 使用者也可用 `SKILL.md` 打包成 Skill。

洗完建議做兩個檢查：每班「總時數」跟洗出來的筆數（含被跳過又展開的分組/輪替課）要對得起來；同一位老師同一天同一節不能出現兩筆「一般課」（隔週輪替、分組選修例外，因為那本來就是設計成可以同格多筆）。

## 資料隱私：DEMO 連結 vs 真實課表

如果你打算把 `index.html` 用 Claude 的 artifact 或其他方式 publish 成一個可分享的公開連結，**不要把真實老師姓名、真實課表直接內嵌進去**——連結一旦分享出去就可能被搜尋引擎索引到，讓全校課表變成任何人都查得到。

建議做法：
- 對外的連結／頁面固定放 DEMO 假資料（本專案內建的 501/504/506/601/610 化名示範資料即可），讓別人點連結進來看得懂功能、玩得動。
- 真實洗好的 JSON（例如 `schedule.json`）**不要**放進公開頁面，直接把檔案傳給要用的同事，請對方在自己電腦上打開那個 DEMO 連結後，用右上「換／匯入課表資料」貼上或上傳這份 JSON。匯入後的資料只存在對方自己瀏覽器的本機記憶裡（見上方「匯入自己的課表」），不會回傳、也不會讓其他打開同一個連結的人看到。

## 檔案

| 檔案 | 用途 |
|---|---|
| `index.html` | 完整單檔前端（含所有功能＋匯入＋本機記憶＋資料體檢） |
| `schedule.sample.json` | 示範假資料，也是格式範本 |
| `wash-prompt.md` | 給 Claude／GPT 洗 PDF 的通用指示 |
| `SKILL.md` | Claude Skill 草稿（已用一份真實 18 班課表驗證過洗資料流程） |
| `HANDOFF.md` | 給接手開發者／LLM 的架構與決策說明 |
| `.gitignore` | 把真實課表／原始 PDF（`private/`、`*課表.json`）擋在 repo 外 |

真實課表請放在不會進版控的地方（本專案用 `private/`，已寫進 `.gitignore`）。

## 緣起與致謝

本專案的發想，始於與 Gemini 討論奕鈞老師做的開源專案「課表查詢系統」 [timetable-demo](https://github.com/littleyi22/timetable-demo)
以及另一位將它改造成「AI 轉檔＋自行匯入」流程的昕哲老師的分享：《半桶水的AI筆記》https://halfmemo.com/ai-notes/ai-timetable-lookup-tool/
讓我看到「把課表 PDF 交給 AI 轉成結構化資料、再用純前端在本機查詢、資料不外流」這條路行得通，也影響了本專案洗課表與匯入的作法。

從與Gemini討論規格和功能，和GPT確認路線拉出架構，最後與Claude Opus定案並做出初步demo，
本專案為獨立重寫、未使用兩位老師的程式碼，定位也不太相同：
兩位老師的工具解決的是**查詢**（查班級、查老師、查空堂），本專案的核心是**調課**——點一節課，算出同班哪位老師能跟你對調。

謝謝這些老師願意把東西開源分享，讓後面的人有肩膀可以站😊
已經拿真實課表（18 班、含分組選修與隔週輪替課）跑過一次，確認資料帶入無誤，並補上第八節限制、隔週提醒、此刻課堂自動更新與本機記憶等功能，希望讓老師們可以調課更順利！
